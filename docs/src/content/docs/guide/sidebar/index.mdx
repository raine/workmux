The sidebar provides an always-visible agent overview pinned to the left edge or
top edge of every tmux window. Unlike the dashboard, which is a full-screen TUI
you open on demand, the sidebar stays on screen while you work.

## Setup

:::caution[Prerequisites]
The sidebar requires [status tracking hooks](/guide/status-tracking/) to be
configured and tmux as the backend.
:::

Toggle the sidebar with:

```bash
workmux sidebar                 # All sessions (default)
workmux sidebar --session       # Current session only, or opt out of global mode
workmux sidebar --position top  # Override configured placement for this toggle
```

By default, the sidebar appears in all existing and newly created tmux windows
across all sessions. Use `--session` to scope it to the current session only,
leaving other sessions untouched. Use `--position left` or `--position top` to
override the configured placement when enabling the sidebar. Running the command
again disables it.

When the global sidebar is active, `workmux sidebar --session` hides it in the
current tmux session only. Run it again to show the sidebar in that session
again without affecting other sessions.

Optionally, add a tmux binding for quick access:

```bash
bind C-t run-shell "workmux sidebar"
```

## What it shows

Each agent is displayed as a tile showing:

- Status icon with spinner animation (working/waiting/done)
- Worktree name and elapsed time since last status change
- Project name and git diff stats (committed + uncommitted lines)
- Optional pull request number and check status for the current branch
- Agent task description

The exact layout, styling, and per-agent icons are fully customizable; see
[Customization](/guide/sidebar/customization/).

## Configuration

Configure the sidebar in your global `~/.config/workmux/config.yaml` or project
`.workmux.yaml`:

```yaml
sidebar:
  # Position: "left" (default) or "top"
  position: left

  # Left sidebar width: absolute columns or percentage of terminal width
  width: 40 # absolute columns
  # width: "15%"  # percentage of terminal width

  # Layout mode for the left sidebar: "compact" or "tiles" (default)
  layout: tiles

  # Dim agents whose status has not changed for one hour (default: true)
  dim_stale: true

  # Row ordering: "recency" (default, most recent status change first),
  # "priority" (agents needing attention first) or "window" (tmux window
  # order - stable rows that match the window list, pairs well with the
  # {window_index} template token)
  sort: recency

  # Group agents into labeled sections: "project" or "session". Unset by
  # default, which keeps one flat list without headers
  group_by: project

  # While grouped, fold each group's stale agents behind a toggle
  # (default: true)
  collapse_stale: true
```

For a horizontal top bar:

```yaml
sidebar:
  position: top

  # Top bar height in rows
  height: 3

  horizontal:
    item_width: 24 # horizontal chip width in columns

  templates:
    horizontal:
      - "{status_icon} {primary} {pane_suffix} {fill} {elapsed}"
      - "{secondary} {fill} {git_stats}"
      - "{pane_title}"
```

Width defaults to 10% of terminal width, clamped between 25 and 50 columns.
When set explicitly, the clamp is removed (minimum 10 columns). Widths above
80 columns use the default width so tmux pane expansion recovers automatically.
Height only applies to `position: top`; set it as a row count for the number of
horizontal lines you want to show. Horizontal item width defaults to 24 columns
and is clamped between 12 and 80. Position changes take effect the next time you
toggle the sidebar off and on. Use `workmux sidebar --position top` or
`--position left` to override the configured placement for that toggle.

## Layout modes

The left sidebar supports two layout modes, toggled with `v`:

- **Tiles** (default): variable-height cards with status stripe
- **Compact**: single line per agent

Tiles show a muted `↓ N more` footer when agents remain below the visible area.
The count includes only hidden agents, not agents above the viewport. The footer
is not selectable and disappears when the final agent is visible. On very short
sidebars, showing the selected tile takes priority over the footer.

Your preference is persisted across tmux restarts. The top bar always uses a
horizontal chip layout, so `v` has no effect there. Horizontal templates render
as many configured lines as the current height allows.

## Grouping

The sidebar is one flat list unless you ask for sections. Grouping suits a
sidebar watching many repositories at once and gets in the way of one watching
a single project, so it is opt in.

Press `t` to try it without changing any config. `group_by` splits the list
into sections, one per repository (`project`) or per tmux session (`session`),
with a header above each section:

```yaml
sidebar:
  group_by: project
  sort: priority
```

Grouping and ordering are independent: `group_by` decides the sections, `sort`
decides the order inside each section. Under `sort: priority` the order is
waiting, done, working, unknown, stale or interrupted, then sleeping, with
recent activity first inside each of those. Waiting and done agents stay at the
top however long they have been waiting, and a working agent drops down only
when interruption detection sees it stop progressing. Sections are sorted
alphabetically and stay in place while agents change status, so rows only move
within their own group. Sleeping agents sink to the bottom of their group
instead of the bottom of the list.

Headers are labels, not agents. They are skipped by `j`/`k` and `g`/`G`, cannot
be clicked or selected, and are not counted by `{idx}`, `{jump_key}` or
`workmux sidebar next|prev|jump <N>`. A header stays visible even when the
session filter leaves a single group, and its count reflects the agents that
sidebar actually shows, sleeping ones included.

When you scroll into the middle of a group, that group's header pins to the top
of the sidebar until the next group's header replaces it. On very short
sidebars, keeping the selected agent visible takes priority over the pinned
header.

Headers are a left-sidebar feature. With `position: top`, `group_by` still
orders the chips but no headers are drawn.

`t` switches between grouped and flat at any time. The choice is a tmux global,
so every sidebar switches together and the agent navigation commands follow the
same order. It outlives a tmux restart and is also available from the command
line:

```bash
workmux sidebar group          # Toggle between grouped and flat
workmux sidebar group project  # One section per repository
workmux sidebar group session  # One section per tmux session
workmux sidebar group none     # One flat list, no headers
workmux sidebar group --clear  # Follow the config file again
```

A runtime choice wins over `group_by` until you change it again, so use
`--clear` after settling on a value in config.

### Grouped templates

A section header already names the project or session, so rows under it can
drop what the header says. Templates under `templates.grouped` apply while
grouping is on:

```yaml
sidebar:
  group_by: project
  templates:
    grouped:
      header: "{group} {fill} {group_count}"
      tiles:
        - "{primary} {pane_suffix} {fill} {elapsed}"
        - "{pane_title} {fill} {git_stats}"
```

`grouped` accepts `compact`, `tiles` and `header`. Anything you leave out falls
back to your ungrouped template of the same name, then to the grouped default,
so templates you wrote before grouping existed carry over and you only write
this block when you want the two presentations to differ.

## Collapsing stale agents

A sidebar watching many projects fills up with agents nobody is waiting on. A
fold puts them behind their group's toggle, out of the way without hiding them
for good. It comes with grouping and is on by default there; set
`collapse_stale: false` to list every agent at full height instead:

```yaml
sidebar:
  group_by: project
  collapse_stale: false
```

An agent counts as stale once it is sleeping, or once an hour passes with no
activity and no working or waiting status: exactly the agents `dim_stale` dims.

A group's stale agents fold behind one dimmed toggle row that says how many it
stands for:

```text
api                              3
▌ ⠋ auth-refresh
▌    api                      2:14
──────────────────────────────────
  ▸ 2 stale
```

A toggle is a row like any other: `j`/`k` stop on it, `Enter` folds and unfolds
it, and clicking does the same. `h` and `l` (or the arrow keys) fold and unfold
the group the selection is in, whether the selection sits on the toggle or on
one of the group's agents, and `s` toggles it. `S` expands every group at once,
or collapses them all when any is open. Expanded agents appear under the
toggle, one line each rather than a full tile.

A group whose agents are all stale collapses further: it has no live rows to
head, so its header is its toggle and the whole project costs one row.

```text
──────────────── STALE ───────────
▸ docs-site                      1
▸ infra                          4
```

Those groups sort below every group that still holds live work, behind a rule
marking where live work ends.

Expansion is shared: it lives in a tmux global, so every sidebar pane shows the
same groups open and it survives a tmux restart. The one thing a pane shows
that others do not is the agent of its own window: a collapsed group still
lists that one agent, so the sidebar never hides where you are, and the toggle
counts only what stays folded.

Numbering follows what the sidebar draws. A folded agent is not a jump target:
it answers to no `{idx}` or `{jump_key}`, `workmux sidebar next|prev|jump <N>`
passes over it, and the numbers close up behind it rather than leaving gaps.
Unfold the group and its agents take their numbers back. `j`/`k` skip folded
agents too, as they skip headers.

## Mouse support

Click an agent tile or top-bar chip to jump to its pane, or scroll to navigate
the list. Requires `set -g mouse on` in your `~/.tmux.conf`.

## Keybindings

| Key     | Action                    |
| ------- | ------------------------- |
| `j`/`k` | Navigate up/down          |
| `Enter` | Jump to agent pane        |
| `g`/`G` | Jump to first/last        |
| `v`     | Toggle layout mode        |
| `f`     | Toggle session filter     |
| `t`     | Toggle grouping           |
| `h`/`l` | Fold/unfold current group |
| `s`     | Fold/unfold stale agents  |
| `S`     | Fold/unfold every group   |
| `z`     | Toggle sleeping on agent  |
| `?`     | Show these keys           |
| `q`     | Open quit confirmation    |

### Session filter

By default, the sidebar shows agents across all tmux sessions. Press `f` to
show only agents in the same tmux session as the current window; press `f` again
to return to all sessions.

The filter also applies to agent navigation hotkeys (`next`/`prev`/`jump`), so
`Alt+j`/`Alt+k` cycle through the current session when the session filter is
active.

You can also toggle the filter from the command line:

```bash
workmux sidebar filter          # Toggle between none and session
workmux sidebar filter session  # Filter to current session
workmux sidebar filter none     # Show all agents (no filter)
```

### Sleeping agents

Press `z` to manually mark an agent as sleeping. Sleeping agents show a 💤 icon
with dimmed colors and are pushed to the bottom of the list, regardless of their
actual status. Under `group_by` they sink to the bottom of their own group.
`sort: window` is the exception: it keeps every agent in window order, sleeping
ones included. This is useful for temporarily deprioritizing agents you don't
need to monitor. Press `z` again to wake them up.

## Agent navigation hotkeys

You can switch between agents from any tmux pane using subcommands. These work
in the same order shown in the sidebar:

| Command                    | Action                               |
| -------------------------- | ------------------------------------ |
| `workmux sidebar next`     | Switch to the next agent (wraps)     |
| `workmux sidebar prev`     | Switch to the previous agent (wraps) |
| `workmux sidebar jump <N>` | Jump to the Nth agent (1-indexed)    |

### Example tmux keybindings

```bash
# Alt+j / Alt+k to cycle agents (no prefix needed)
bind -n M-j run-shell "workmux sidebar next"
bind -n M-k run-shell "workmux sidebar prev"

# Alt+1..9 to jump directly
bind -n M-1 run-shell "workmux sidebar jump 1"
bind -n M-2 run-shell "workmux sidebar jump 2"
bind -n M-3 run-shell "workmux sidebar jump 3"
# ...
```

## How it works

The sidebar is a bit of a hack on top of tmux's pane system, but it works quite
well. It uses a daemon + client architecture with event-driven rendering:

1. **Toggle on** (`workmux sidebar`): creates a tmux pane on the left or top
   edge of every window, starts a background daemon, and installs tmux hooks.

2. **Daemon**: a single headless process that polls tmux state every 2 seconds
   (or immediately when signaled via SIGUSR1). It reads agent state from a
   context-scoped filesystem cache, queries tmux for pane geometry and active
   windows, then pushes snapshots to all connected sidebar clients over a Unix
   socket. Unchanged records are reused without loading or parsing their JSON.

3. **Clients**: every tmux window gets its own sidebar pane running a separate
   `workmux _sidebar-run` process. Each process connects to the shared daemon
   socket, receives snapshots via a background reader thread, and renders
   independently. The main thread blocks on a channel, only waking when new
   data arrives or a spinner tick is needed. Rendering is skipped entirely for
   inactive windows. This event-driven design keeps CPU usage near zero when
   idle.

4. **Hooks**: tmux hooks handle lifecycle events:
   - `after-new-window` / `after-new-session`: automatically adds a sidebar pane
     to newly created windows
   - `window-resized`: reflows the layout tree in every sidebar window, keeping
     all sidebars at the correct width or height regardless of which window was
     resized
   - `after-select-window` / `client-session-changed` / `after-kill-pane`:
     signals the daemon for an immediate refresh

5. **Layout reflow**: when the sidebar is added or the terminal is resized, a
   layout tree parser reads the tmux `#{window_layout}` string, scales the
   content subtree proportionally, and applies the result atomically via
   `select-layout`. This preserves existing pane proportions (e.g. a 70/30 split
   stays 70/30).

6. **Toggle off**: kills all sidebar panes, reflows content panes to fill the
   freed space, stops the daemon, and removes hooks.

### Resource usage

Because tmux has no concept of a pane that persists across all windows, each
window runs its own `_sidebar-run` process. Each one uses roughly 15 MB of
resident memory, and the shared daemon (`_sidebar-daemon`) uses about 16 MB. With
five agents running, total memory footprint is around 90 MB. CPU usage is near
zero when idle thanks to the event-driven architecture.
